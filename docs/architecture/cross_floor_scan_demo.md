## 验收范围

在不启动 Gazebo 的条件下，通过一个 RViz 窗口完成并观察以下顺序任务：

1. 对应一楼 Carter 从中心区域驶向外圈，再到楼梯发送侧。
2. 对应 Go2 与一楼车完成演示交接，经该楼梯上至二楼并站定。
3. 所属侧二楼 Carter 从停车区驶向楼梯接收位。

三个智能体均使用 SCAN-Planner，使用隔离 namespace、完整 URDF/TF、仓库三维
PCD、局部点云、规划轨迹及已走路径进行 RViz 可视化。

## 启动方式

```bash
cd /Users/lab4099/Desktop/Mujoco/work/scripts
./run_cross_floor_scan_rviz.command ne   # 东北
./run_cross_floor_scan_rviz.command nw   # 西北
./run_cross_floor_scan_rviz.command sw   # 西南
./run_cross_floor_scan_rviz.command se   # 东南
```

脚本使用独立 `ROS_DOMAIN_ID` 和 Cyclone DDS，避免上次中断遗留的 TF、
`robot_description` 或 Fast DDS 共享内存锁污染本次运行。

- 一楼东北发送点：`STAIR_NE_F1_SEND = (20.30, 18.30, 0.0)`。
- Go2 二楼路线验收点：`(14.2929, 11.2929, 4.56)`。

- `car_f2_2` 规划位姿采用车体中心高度：`(9.5, 6.5, 4.70)`。

场景语义坐标以 `config/scene.yaml` 为唯一依据。此前二楼车错误地在
`(9.0, 5.2, 4.70)` 提前结束，已于本次验收前修正，运行脚本的成功判定也已
同步到 `(9.5, 6.5, 4.70)`。

## 通过标准与结果

- RViz 中车、狗完整模型及仓库三维点云同时可见，RobotModel/TF 不爆红。
- 三段任务必须严格按顺序启动，前一段到站后才进入下一交接段。
- 一楼车到发送侧、Go2 到二楼出口、二楼车到接收点。
- 二楼车不得在旧点 `(9.0, 5.2)` 提前判定成功。
- 终端最终输出 `CROSS-FLOOR SCAN TASK PASS`。

结果：以上项目经用户观察验收通过。
